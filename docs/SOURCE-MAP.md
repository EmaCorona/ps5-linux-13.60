# Source map — what is live, what is generated, what is history

A new reader must be able to tell these apart without archaeology. If a file is not in this list, it
is either new (add it) or it should not be here.

## Live code (this project)

| path | what it is |
| --- | --- |
| `source/main.c` | entry point, firmware dispatch, standby request |
| `source/core/`, `source/hw/`, `source/boot/`, `source/manifest/`, `source/offsets/`, `source/hv/defeat/` | first-party implementation |
| `source/shellcode/*` | freestanding blobs **built by the build** (`Makefile`, `takeover.S`, …) |
| `include/**` | first-party headers |

## Vendored (upstream code, kept for its licence notices)

| file | origin |
| --- | --- |
| `source/byepervisor/khook.c`, `include/byepervisor/khook.h` | Byepervisor-Reborn, verbatim |
| `source/byepervisor/kdlsym.c`, `include/byepervisor/kdlsym.h` | Byepervisor-Reborn, adapted |
| `source/byepervisor/paging.c`, `include/byepervisor/paging.h` | Byepervisor-Reborn, adapted |

Their original headers (including `AGPL-3.0-or-later`) stay as they are — see
[`THIRD-PARTY.md`](THIRD-PARTY.md).

`include/byepervisor/khook_state.h` sits in the same directory but is **not** vendored: it is this
project's state model (Task 14). The directory name says "vendor", not the header.

## Host tools (not shipped in the payload)

`tools/*.py` (verifiers, registry and payload checks, generators), `tools/pl5-*.c` (payload-side
diagnostic helpers built separately), `tests/run_tests.py`.

## Generated — never edited, never committed

`bin/*.elf`, `source/**/*.o`, `source/shellcode/*/[*.bin]`, `source/shellcode/*/[*.h]` (the embedded
blobs), `tools/pl5-offsets.elf`, `.pl5-config.stamp`. All of these are in `.gitignore`; they are
build output, not sources. If one of them appears in a diff, something is wrong.

## History, not instructions

`docs/*.md` records investigations, including dead ends and superseded plans. The documents that are
*current* are named in [`README.md`](README.md); the chronology in `1360-port-status.md` and the
narratives in `analyst-recap-1360.md` describe the state at the time they were written.

`docs/upstream-ps5-linux-loader-README.md` is a **verbatim copy of the upstream README** kept for
reference. It is not this project's documentation and its installation steps may not apply here.

## Known dead / historical artifacts

| artifact | status |
| --- | --- |
| `solution/shellcode/hv_takeover/takeover.c` | **not present in this branch and never tracked here** (`git ls-files solution/` is empty). Older notes call it dead code that still carried 13.20 defines; the ambiguity is gone because the file is gone. The canonical blob is `source/shellcode/hv_takeover/takeover.S`. |
| `hv_boot.bin` / `hv_boot.h` | generated by the build, **not embedded**: nothing references `hv_boot_bin`. `tools/check_payload_static.py` asserts exactly that, so it cannot silently become "the implementation". |
| `db_trampoline.{S,bin,h}` | the Stage-1 #DB trampoline (Task 13.4): assembled and structurally verified on every build, **not staged into the image** unless the hook is armed (`PL5_1360_ARM_HOOK=1`, off by default). The payload check records it as generated-not-embedded for the same reason as `hv_boot`. Design: [`1360-khook-design.md`](1360-khook-design.md). |
| `source/hv/defeat/hv_defeat_{0304,0506,0607}.c` | legacy vectors (fw < 0x0800). Live code for those firmwares, not for 13.60. |

## Duplicated upstream references

`docs/upstream-ps5-linux-loader-README.md` duplicates upstream text by design (a reference copy);
the vendored `byepervisor` files duplicate upstream code by design (a fork). Both keep their original
notices. No other file in the tree is a copy of upstream code.
